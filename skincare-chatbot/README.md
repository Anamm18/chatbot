# Skincare Recommendation Chatbot

A retrieval-grounded chatbot that recommends skincare ingredients based on a
user's stated skin concern. It uses semantic search over an INCI ingredients
dataset to find relevant matches, then a free LLM (Groq) to write a grounded
answer — and refuses to answer anything unrelated to skincare.

## How it works

1. **Dataset**: `ingredientsList.csv` — INCI ingredient data (name, what it
   is, what it does, who it's good for, who should avoid it).
2. **Embeddings**: each ingredient's combined text fields are embedded once
   with `all-MiniLM-L6-v2` (local, free, no API) and saved to
   `Ingredients_embedding.npy`, alongside the cleaned data in
   `ingredient_data.pkl`.
3. **Retrieval**: a user query is embedded the same way, and matched against
   the ingredient embeddings with cosine similarity.
4. **Off-topic gate**: if the best match's similarity score is below a
   threshold (default `0.35`), the app skips the LLM entirely and returns
   a fixed "not my area of expertise" message — no API call, no guessing.
5. **Generation**: if there's a good match, the top-k matched ingredients
   are passed to Groq (`llama-3.1-8b-instant`) with a system prompt that
   restricts it to only use the provided data and cite ingredient names.

## Setup

```bash
uv init skincare-chatbot   # skip if the folder already exists
cd skincare-chatbot

uv add sentence-transformers pandas numpy scikit-learn streamlit groq python-dotenv
```

Create a `.env` file in the project root with your free Groq API key
(from console.groq.com):

```
GROQ_API_KEY=your-key-here
```

## Run it

**1. Build the embeddings first**, by running through `Skincare_ChatBot.ipynb`
top to bottom (this generates `Ingredients_embedding.npy` and
`ingredient_data.pkl` in the project root).

**2. Launch the chatbot UI:**

```bash
uv run streamlit run app.py
```

**3. Try it out** — on-topic questions should get grounded, cited answers;
off-topic questions ("what's the capital of France?") should get the fixed
refusal message.

## Tuning

- `SIMILARITY_THRESHOLD` in `app.py` (default `0.35`) controls how strict the
  topic gate is. If valid skincare questions are getting refused, lower it.
  If off-topic questions are slipping through, raise it.
- `TOP_K` (default `5`) controls how many matched ingredients get passed to
  the LLM as context per query.
- `GROQ_MODEL_NAME` can be swapped to try other free Groq models, e.g.
  `llama-3.3-70b-versatile` for higher-quality but slightly slower answers.

## Known limitation

The dataset currently only covers **ingredients**, not full products — so
recommendations are ingredient-level (e.g. "look for niacinamide and
salicylic acid"), not specific product names. A products dataset (e.g. the
Dermstore or Sephora datasets) can be added later and joined in the same
retrieval pipeline if product-level recommendations are needed.
